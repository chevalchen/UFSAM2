# EXP-007｜SAM2-Small 与 Large 的 SANSA 训练成本对比

- 状态：PREPARED / UNEXECUTED。无 GPU 实测、无精度结论。
- 日期：2026-11-13。
- 分支：`exp/EXP-007-small-backbone-benchmark`，父提交 `5a8d4cf`。
- 目的：在用户的两张 RTX 3090 上确定 Small 相对 Large 能减少多少训练步时间和显存，再决定是否训练 Small 的正式少样本分割基线。
- 本地职责：接入与方案；下一写入方：服务器 Codex。当前没有运行中的本实验任务。

## 1. 范围与假设

预计 Small 能降低编码器内 adapter 训练成本，但不能由参数量推算训练加速，也不能预设部件精度下降多少。此次先测性能，不做完整 benchmark 精度复现，不同时训练其他四个对比方法，不开展蒸馏。

比较原版 SAM2-Hiera-Small 与 SAM2-Hiera-Large，均采用 SANSA，adapter stages=[2,3]，channel_factor=0.3，mask prompt。不要混用 SAM2.1 权重。Small 没有已验证的 SANSA adapter；性能试验两者都使用基础模型预训练权重和新初始化的 adapter，不给 Large 单独加载已训练 adapter。合成数据的损失仅检查计算路径，不代表模型质量。

## 2. 已准备的内容与待验证事项

- `UFSAM2/opts.py`、`UFSAM2/util/path_utils.py` 增加 small 入口。
- `UFSAM2/models/sam2/sam2_configs/sam2_hiera_s.yaml`：沿用原版 tiny 的公共设置，Small stages=[1,2,11,2]、global_att_blocks=[7,10,13]。服务器须与官方原版 Small 配置核对。
- `UFSAM2/benchmark_backbone.py`：单进程合成输入的完整 adapter 训练步计时；包含前向、仓库 focal/dice loss、反向、梯度裁剪和 AdamW 更新，排除数据加载和 CPU→GPU 拷贝。输出参数量、逐步耗时、allocated/reserved 显存、环境与 checkpoint SHA256。
- 未做 GPU smoke test。构造器当前使用 strict=False；服务器应核查 checkpoint 的 missing/unexpected keys，缺失项只允许已知的新 adapter 和原流程明确关闭的组件，不能悄悄接受编码器漏加载。
- 尚未验证真实数据训练吞吐，也未测冻结编码器后的新增模块路径。脚本结果只适用于 adapter 训练，不可外推到 EXP-005/006 的缓存路径。

## 3. 服务器执行步骤

1. fetch 此分支，在独立 checkout 或 worktree 接管，避免占用其他活跃实验目录。检查两张卡的进程，使用空闲卡，不终止他人任务。
2. 使用已有 SANSA 环境，验证 Small 和 Large 的 checkpoint/config 一致。记录实际 Python、PyTorch、CUDA、GPU、代码 SHA、权重 hash。
3. 分别运行 2 个 warmup + 2 个测量步 smoke，检查输出尺寸、有限损失、非零 adapter 梯度，以及只有 adapter 可训练；检查冻结权重未变化。若有实现问题，直接修复并提交。
4. 修复完成后提交代码，在干净执行快照测量。两模型在同一张空闲 3090 上顺序运行，独立进程，不把不同 GPU 型号/负载差异计为模型收益。
5. 首轮固定 batch=1，分别测 1-shot 和 5-shot；输入 1024，先 FP32 对齐当前 engine，再单独对两者测 BF16。不要仅给 Small 开混合精度。
6. 每配置预热 5 步、测量 30 步；交替 Large→Small、Small→Large，共 3 轮独立进程。遇到 OOM 记录失败配置，不将减小 batch 后的结果与另一模型原 batch 直接比较。默认不启用 compile、activation checkpointing 或 DDP。
7. 合成计时完成后，从实际训练 loader 固定一小批图像/mask，对两者测相同训练路径，并补一组含数据加载的端到端计时。记录清单、裁剪和分辨率；不更改原始数据协议。分别报告纯训练步与端到端结果。
8. 可选补充冻结整个编码器的推理成本，作为后续特征缓存的估计；与 adapter 训练单独列出。

从仓库内 `UFSAM2/` 目录运行，替换下面的绝对路径；每次输出使用新文件名：

```bash
CUDA_VISIBLE_DEVICES=0 python benchmark_backbone.py --model large --checkpoint /path/sam2_hiera_large.pt --output /path/results/large_1shot_fp32_r1.json --shots 1 --precision fp32
CUDA_VISIBLE_DEVICES=0 python benchmark_backbone.py --model small --checkpoint /path/sam2_hiera_small.pt --output /path/results/small_1shot_fp32_r1.json --shots 1 --precision fp32
```

脚本暂时仅提供合成数据入口，真实 batch 计时由服务器按现有 loader 最小接入。大文件、权重与原始日志留在服务器输出目录，不提交 Git。脚本 `--size` 是输入尺寸；模型内部可能重新缩放，主实验固定 1024，必须同时记录 internal_image_size。

## 5. 决策与交接

这次不设置精度门槛，不宣称 Small 优于 Large。依据实测时间和显存报告 Small 是否明显降低日常迭代成本；若几乎无加速，分析 memory/decoder、同步或数据加载是否占主导。只有性能结果确认后，再讨论 Small adapter 的完整训练预算和部件精度 benchmark。
