## 2. 单一假设

> 在保持 SANSA 主干、memory bank 和 decoder 固定的 COCO-20i base-class 5-shot 任务中，仅在 memory-conditioned query feature 进入 mask decoder 之前加入局部 support 原型条件 residual，能比全局 support 原型和同容量 generic residual 更好地恢复缺失语义区域，并改善 aggregate class-mIoU，而不是仅依赖额外训练或参数量。

首阶段只验证语义修复算子；不训练 uncertainty/risk/action-value gate。Oracle routing 只能诊断修复上限，不能替代部署性能。

## 3. 拟冻结设计（PROPOSED，尚未签署）

### 3.1 唯一插入点与确定性原型

- 单一插入点：SANSA `_compute_decoder_out_w_mem` 中 memory attention 输出 `F_m` 与 `_forward_sam_heads` 之间。保留五个完整 support memories、位置编码、object pointers 和原有 query decode 路径。
- 使用既有最终 encoder feature 与 nearest-neighbor resized support GT mask，从每个 support 的前景特征中形成固定 `K=4` 个局部原型；总计 20 个 prototype slots。特征维度和空间尺寸从 runtime 获取，不写死 64×64。
- 拟采用 L2-normalized foreground tokens 上的 deterministic farthest-point initialization（首个为 row-major 最小索引，距离相同取最小索引）加 10 次 spherical k-means；空 cluster 保留上轮中心，token 少于 4 时复制已有中心。foreground 为空则停止并报告输入问题，不静默替代为 query GT。
- 对 query 原始特征 `F_q` 与 prototypes 做 cosine matching，固定 softmax temperature `1.0`；加权重建与 `F_q` 同维度的 support-context map `P_local`。不学习聚类、temperature 或 prototype 数量。
- Residual 输入 `[F_m, F_q, P_local]`；`1×1` 投影到 width `32`，GroupNorm(8 groups)+GELU，两层 depthwise `3×3` + pointwise `1×1` blocks，最后零初始化投影回原维度。输出 `F_m + 0.1*tanh(R)`。当前只是拟定架构，需接口审计后才冻结 JSON。
- 同一 decoder 输出同一阈值 `0.5` 的预测；主结果不需要 baseline 后的第二次 decode。Matched B0 和 ORACLE 诊断可共享缓存额外解码，统计成本与部署路径分别报告。
- 默认关闭时必须 binary exact-equivalent；开启但零初始化时也要求 identity。全程不增删 memory entry、不加 query pseudo-memory、hflip、MTP、BRM、mask refiner 或其他已存在候选。

### 3.2 数据与权重范围

- 拟用 strict-FSS COCO-20i fold 0、source split `train`、5-shot mask prompts；首先只作 base-class screen。Baseline 采用该实验同 SHA、同 checkpoint、同 episode 的 matched B0。
- 初始化拟用 accepted official fold-0 adapter 与 SAM2-Large；具体 paths/hashes 必须在正式冻结时重新签名，不能仅引用旧文件名。
- 拟定 train/calibration/validation=`1200/600/600`，query/support image identities 在三个 partition 间完全不重叠；同 partition episodic reuse 必须由 manifest 固定。
- 必须生成新 manifest；将前序实验已经观察过的 validation query/support image identities 排除出本实验的 calibration 和 validation。可行性和类覆盖尚待审计；不能把已经反复查看过的数据宣称为新的独立确认集。
- Train 只监督新增模块；calibration 只用于预先指定的 checkpoint 选择；validation 在模型和配置锁定后统一评估一次。Novel-query labels 保留给最终评估，当前方案不读取；不作 PASCAL/part generalization claim。

### 3.4 训练范围与预算草案

- 冻结 SAM2 backbone、官方 AdaptFormer、memory encoder、memory attention、prompt encoder 与 mask decoder；只训练 C1/C2/C3 的新增 residual 参数，固定原型构建无参数。没有未训练随机图网络作为正式方法。
- Training seeds `0,1,2`；每个 row/seed `2400` optimizer updates，batch size 1，按新 train manifest 固定顺序循环两遍。共 9 个小模块训练 run、`21600` updates；这是未来预算上限，不表示已启动。
- AdamW：learning rate `1e-4`、weight decay `1e-2`、固定学习率；loss=`BCEWithLogits + soft Dice`，两项各权重 `1`。不搜索 width/K/temperature/loss weight。
- 每 `600` updates 在固定 calibration set 评估，选择 aggregate class-mIoU 最佳 checkpoint，同值取最早 step；不得用 validation 选择 epoch。所有训练对照同频率、同次数。
- 硬停止：非有限 loss、identity/default-off 失败、数据泄漏、缺失匹配样本或 provenance 失败立即停止，保留 artifacts，归为 INCONCLUSIVE；不得为赶时间缩短某一对照训练或删除失败 seed。
- 只用可用 GPU，不干预他人进程。正式预算需先通过单 episode shape/default-off smoke 和短步 CPU/GPU technical pilot 测定显存、时长；pilot 标为 DIAGNOSTIC_ONLY，不作科学判定。若预算不可接受，在未运行正式实验前回到 Idea/Decision，不临时减半训练。

### 3.5 拟定指标与停止规则

- Primary：aggregate class-mIoU，`C3−C1`；supporting：`C3−C0`、`C3−C2`、FB-IoU、worst-decile episode IoU、latency/peak memory、C4 和 C8。
- 建议进入后续设计的条件：三 seed 平均 `C3−C1 ≥ +0.5` 点，且 `C3−C2 ≥ +0.5` 点、`C3−C0 ≥ +0.5` 点；三项按每 episode 先平均三 seed 的 paired foreground-IoU effect，10000 次 paired percentile bootstrap、seed 0，95% CI 下界均大于 0。另报告每个 seed 和 seed SD；CI 明确只反映 episode sampling。
- 每个 C3 seed 相对同 seed C1/C2 和 C0，FB-IoU 下降均不得超过 `0.2` 点、worst-decile 下降不得超过 `0.5` 点。所有必要条件共同满足才允许下一个设计阶段，仍不是 KEEP。
- 若完整有效 evidence 不满足上述组合条件，DROP 该具体算子；若只有 ORACLE 改善，保留诊断但不自动训练 selector；缺失或损坏 evidence 为 INCONCLUSIVE。
- 不在此次 proposal 加入 SANSA adapter 的联合微调。若以后提出联合微调，必须独立设计“原 SANSA / 新模块 × 冻结 / 等预算微调”控制，不能把额外 backbone 训练归因为本模块。
