## 1. 从两篇论文和已有实验出发

官方 SANSA 通过适配后的 SAM2 特征和 support memory 将参考语义传给 query。标准 query 解码不传入点，因此可以在 memory attention 后缓存条件特征 `F0`，复用同一个 prompt encoder 和 mask decoder 进行对照。这里固定 support 顺序、记忆内容和模型参数，检验 query 端的显式提示是否能补足一次解码的错误。[SANSA 论文](https://proceedings.nips.cc/paper_files/paper/2025/hash/ac6ab84809cef04dbe11e9b80d63c281-Abstract-Conference.html) · [官方推理代码](https://github.com/ClaudiaCuttano/SANSA/blob/f562b56/models/sansa/sansa.py)

PR-MaGIC 用 mask decoder 的梯度更新 query embedding，据此重新做语义匹配并选点，再用原始 embedding 解码候选。其 top-1 选择用 support–query 相似度打分，论文也报告了部件定位失败和 oracle 与实际选择之间的差距。EXP-006 借用「梯度改变提示、稳定特征负责解码」的机制。首轮点来自 MTP，第一阶段使用确定性梯度，并单独检验选择器，因此属于面向 SANSA 的适配实验。[PR-MaGIC §3.2–3.3、§4.4](https://arxiv.org/html/2604.12113v1#S3)

历史 MTP 的 `t085` 只触发 34/4000 个 episodes，记录中的 +0.18 点来自与论文数值的比较。EXP-001/003 表明候选空间和可部署选择能力需要分别评估，EXP-004/005 表明语义信号需要错位或打乱对照。首轮按用户决定，**对完整清单逐 query 尝试采点，关闭基于置信度的触发门控**。默认把不回退的末步 mask 作为主比较，同时从同一候选缓存离线计算原 MTP 质量回退和 GT oracle。[历史 MTP](https://github.com/chevalchen/UFSAM2/blob/219ac83/UFSAM2/EXPERIMENT.md#24-module-c) · [EXP-001–005 总结](RESEARCH_SUMMARY_2026-11-02.md)

## 2. 第一阶段｜先验证梯度是否产生更好的候选

### 推理步骤

1. 官方 SANSA 生成初始 logits 和 mask `M0`，缓存 `F0` 及高分辨率特征。复用旧 MTP 的选点规则生成共同首轮点 `P0`，默认 1 正 1 负，得到 `M1 = D(F0, P0)`。候选坐标统一转到 SAM2 输入坐标系。
2. **静态版**在 `M1` 上用相同正负点规则重新排序。通过相同的空间去重规则获得新的点集，点数、首轮点、允许修改的点及候选选择规则与梯度版一致。
3. **梯度版**缓存第 2 次解码 `M1` 的计算图，只对 `F0.detach().requires_grad_(True)` 求梯度。一个可实现的起点是对未二值化的 logits 构造前景与背景分开归一化的目标 `J = mean(L on A+) − mean(L on A−)`。锚点 `A+ / A−` 从停止梯度的 `M1` 高置信区域取得，稀疏分布并覆盖现有提示，避免大区域主导梯度。锚点不足时用静态结果并记录覆盖率。提议用特征梯度的空间能量 `||∇F0 J||₂` 对静态候选重排，分别在正、负候选集合内归一化。正负标签仍由候选区域定义，梯度幅值只提供优先级。只做一步，用重排后的点 `P1` 和原始 `F0` 解码 `M2`。这是确定性的梯度采点代理，其有效性由下述对照决定。
4. 对静态和梯度版，主口径输出 `M2`。同一轮另外计算无 GT 的原 MTP 质量规则在 `{M0,M1,M2}` 中的选择结果，以及基于 query GT 的候选 oracle。只有初始正点缺失时输出 `M0`，第二轮无有效新点则输出 `M1`。所有回退样本计入全量指标，并报告无有效点、点集未改变、mask 未改变的比例。选择器诊断复用候选缓存，避免选择后的输出影响其他候选。

| 组别 | 每个有效 query 的 SAM head 前向预算 | 用途 |
| --- | --- | --- |
| B0 官方 SANSA | `M0` | 匹配基线 |
| S1 单次 MTP | `M0, M1` | 量化初始自动点的收益，由共同候选直接统计 |
| S2 静态重采样 | `M0, M1, M2-static` | 控制点提示与额外解码收益 |
| G2 梯度重采样 | `M0, M1, M2-grad` + 1 次反向 | **主对比 G2−S2** |
| G2-shuffle 梯度错位 | 复用梯度响应，空间置换后生成一个额外候选 | 若 G2 有信号，在固定清单检验空间对应是否重要。固定种子，保持正负候选域及域内梯度分数分布 |

以实际 head 调用计成本。S2 与 G2 前向及候选预算一致，额外反向的开销单列。候选集按组独立计算 oracle，固定同一指标。每个 query 的 oracle 以最高前景 IoU 选 mask，再汇总 class-mIoU 和 episode IoU，两者分别报告。

### 把错误定位与解码器可修复性分开

在预先固定的小型诊断子集做 **GT 纠错点 oracle**。从 `M1` 的漏分和误分连通区域内部各取一个纠错点，按同样的点数和一次额外解码预算生成候选。GT 只进入这条离线诊断路径。若连 GT 点都很少改善结果，优先调查稀疏点对当前解码器是否足够，以及小目标或多实例是否需要 dense mask prompt。若 GT 点有效而 G2 无效，说明当前选点信号或搜索域可能是瓶颈。额外记录正点命中真实前景、负点命中真实背景、点是否覆盖漏分或误分区域，以及点位变化与 IoU 变化的对应关系。

## 3. 第二阶段｜由第一阶段结果决定做什么

- **G2 的候选明显更好，部署选择收益偏小**。优先测试候选选择。用 memory attention 前、同层的适配后特征从 support mask 提取前景原型，可从标注的相邻部件或目标周边背景提取负原型。以固定语义图衡量候选对高相似区域的覆盖，以及对冲突区域的泄漏。对照原 MTP 质量分数、前景平均相似度和空间错位语义图。把对候选集合的离线选择与提示生成分开，先确认选择器能回收多少 oracle 空间。
- **GT 点能修，但 G2 跟 S2 接近**。先跑成本低的 **前向语义采点**。对初始 mask 外的高语义相似区域补正点，在高前景响应但低目标相似度的区域放负点。若这条路线更强，采用它作为研究候选。若仍值得探索梯度，可在相同前向语义采点上加入梯度增量，并引入前景、邻部件的局部对比目标，检验是否能纠正高置信语义错误。对梯度幅值偏向边界或噪声的情形，可改测有符号的 logit 响应，例如在仅用于打分的临时特征上估计方向导数，候选仍由 `F0` 解码，额外前向计入对照预算。
- **GT 点和候选 oracle 都缺乏实用空间**。结束当前稀疏点算子，记录适用边界。另行评估多尺度或低分辨率 dense mask prompt 是否能覆盖多实例、细长结构及整块漏分。门控只在算子已有收益后用于精度与成本折中。

## 4. 数据、统计和决策

- **开发**。先做小批 smoke，再在 COCO-20i fold 0、5-shot 的固定开发清单做无门控筛选。权重优先采用官方 SAM2-Large 和同一 fold adapter。部件错误诊断使用单独的 PASCAL-Part / PACO-Part 开发清单，保留 object crop，记录小部件、相邻部件混淆、边界偏差、漏实例四类。按对象面积和初始 IoU 分层，使用 GT 的分层仅用于事后诊断。每个 episode 独立，固定 support 顺序、图像几何、mask 阈值及 multimask 策略。检查与既往用于选择超参的图片、episodes 是否重叠，并明确证据边界。
- **正式验证**。开发锁定后再选独立清单，优先 COCO novel fold 与未参与调参的部件数据。冻结执行 SHA、episode manifest 及其 hash、权重 hash、模型与数据配置、随机种子、评估脚本、数据可用性和成本预算。保留 matched B0 和所有消融的 per-episode 记录，清单及小型汇总进 Git，权重和大结果放服务器输出目录。
- **指标**。主比较用全量 class-mIoU 的 G2−S2，同时报告 G2−B0。另报配对 episode 前景 IoU、Boundary IoU、FP/FN、变差比例、最差十分位表现、候选 oracle 与实际选择之间的差值。配对不确定性保持同一 episode 的各组绑定。若同一 query 重复出现，按 query image 成簇抽样，并在每次重采样中重算 class-mIoU，单列 episode IoU 的区间。延迟报告统一设备和精度下的同步计时及显存峰值。
- **决策**。方案阶段暂不冻结通用数值阈值。正式验证前按开发方差和额外反向开销定最小有意义增益、尾部护栏和预算。`KEEP` 需要 G2 超过等候选预算的 S2、相对 B0 有实用净收益、空间错位对照支持定位机制，且延迟和尾部可接受。`REVISE` 适用于 oracle 有明显空间但选点或选择器存在可定位瓶颈。`DROP` 适用于充分配对比较下梯度无额外收益，或 GT 点 oracle 也缺乏实用空间。`INCONCLUSIVE` 用于梯度或坐标验证失败、样本不足、或区间仍跨越实际决策边界。正式阈值与最终数据在实现验证后、正式跑分前记录为后续版本。
