# EXP-009｜支持示例决定 SANSA-Small 的输出粒度

**问题。** 给定 K 对支持图及掩码、一个无标注查询图，同一份模型能否识别示例所指的范围，在具有相同空间锚点的候选中选出同类部件或整个对象？主线固定 EXP-008 第 5 轮 Small adapter，无需查询点击、类别名、测试集身份或额外部件训练。当前是可运行的推理原型，收益待测。

## 概念和代码依据

| 来源 | 原方法实际信号 | 本实验取舍 |
|---|---|---|
| [UnSAMv2](https://github.com/yujunwei04/UnSAMv2) | [评分函数](https://github.com/yujunwei04/UnSAMv2/blob/main/granularity_divide_and_conquer/compute_granularity.py) 在候选组内用面积平方根做 min–max 归一化，映射到 0.1–1，等面积时返回 1。论文用伪 mask–粒度对监督连续控制嵌入和专用 mask token。 | 可借用同一对象的候选尺度次序。单张 support GT 不提供查询图对应的控制值，直接搬评分函数或换预训练头都无法验证跨图对齐。若选择上界小，再试训练候选生成器。 |
| [GraCo AGG 源码](https://github.com/Zhao-Yian/GraCo/blob/HEAD/any_granularity_generator.py) | scale 用区域面积除原对象面积；semantic 在区域内点一次，用交互模型概率图在区域、对象内的极差之比作代理。后者也受点击、预测器和极值影响。 | 最值得迁移的是把两个信号独立消融。EXP-008 的对象框裁剪不等于父对象掩码，不能用查询 GT 构造分母；本实验直接计算可观测的图像占比。 |
| [UniGraCo](https://github.com/Zhao-Yian/UniGraCo/tree/f2101d771af842143166464b7396cc6cfb420156) | 统一处理可选控制信号，包含细粒度掩码生成、语言表示和交互预测路径；用户手动控制的任务允许外部提供粒度信息。 | 借用缺失信号时退回已有控制的思路。当前任务仅提供支持掩码，文本滑块、测试类名、额外点击均会改变任务协议。 |

**两条量不能混称。** 语义粒度是目标在父对象层级的位置；候选嵌套只是其可检验的代理。耳朵特写与全景中的耳朵语义层级相同，面积占比可差一个数量级。几何量定义为掩码面积/实际模型输入视野面积；部件基准的视野是裁剪后的对象框。父对象面积比是第三种量，需要父对象掩码。并排的手和脚可能面积、层级都相同，类别对应仍依赖 SANSA 的记忆特征。

## 已接入的模块

- 原始 SANSA 用预测 IoU 选三个 query multimask 中的一个。冻结候选和 checkpoint，模块在同一位置重排。原生候选和输出 token 仍按同一索引选择，后续记忆同步。off 为默认，无新增权重。
- area 使用支持/候选前景占比的平方根距离。nesting 从每个有效支持掩码内部取一个确定性正点，用已缓存图像特征额外解码一次，把已知掩码和得到的候选比较。两区域若覆盖较小者至少 90%，且面积比不超过 0.8，则记为有向包含边。层级估计为「更小的亲属数 / 有效亲属数」，无边记为未知。查询候选按同一规则与兄弟候选比较。支持侧点提示与查询侧记忆解码产生的候选族可能不对称，这是要测的失效来源。
- 各维取有效参考中位数，扣除粒度距离（每维权重暂定 0.1）；层级只有在基线候选、备选和支持侧都可比时才参与。禁止切换到与原赢家空间分离的候选，原赢家为空或平分时保留。both 同时使用两维。新增开销主要是 nesting 每个非空支持一次解码，无额外图像编码。

## 实验顺序与判断

1. **候选诊断。** 同一权重、seed、fold、查询与参考 ID 跑 off 并记录三个候选的逐例交并数。报告基线、按逐例真值 IoU 选择候选的诊断值、三候选几乎一致/全部漏检比例。逐例最优不等于按类累计交并后的数学上界。按小部件、不同父类分层，抽查“同一部件/整对象”与“不同实例/错误类别”。若现有候选普遍给不出正确范围，应转向生成阶段。
2. **同预算消融。** off、area、nesting、both 使用同一候选集合，再加入跨 episode 打乱支持描述（同 shot、同面积分箱）和固定偏好小候选。检查正确切换/错误切换的计数、层级可用率、部件漏检与误扩张、峰值显存及逐例时延。冻结权重时不同镜头下同一部件应保留层级偏好；通过保持内容和标签的补边变换改变画幅，占比明显变化时重测 area 与 nesting。防止把偏好小面积解释成语义迁移。
3. **成功标准（建议在开发集后冻结）。** 主指标为折等权的类 mIoU。两个外部部件集的配对改变量分别报告，按类别/查询分层 bootstrap；不把重复 query 当独立图像。FSS-1000 的 1/5-shot mIoU 各自预设非劣界，例如 −0.5 个百分点，95% 配对区间下端均高于该界；同时报告 FB-IoU。若 nesting 不优于面积匹配和打乱支持的对照，只保留有证据的结论。阈值示例尚未获用户确认。
4. **有监督备选。** 若有候选空间却无法选对，可冻结主干，仅在 PACO 训练划分上训练小评分头。输入为 IoU 预测、支持/查询候选层级、占比距离和有效标志；用三候选中真实 IoU 最高者作分类标签，或以真实 IoU 差作排序监督。若候选空间不足，再单独实验 UnSAMv2 式条件 token：用同一位置的父/子掩码配对，在固定支持对象、切换支持层级时监督不同查询输出，BCE+Dice；另设同参数无粒度条件对照。使用人标 PACO 后单列表格，不能声称免部件监督。保持 FSS 可用原训练域对象 episode 回放，FSS 测试图不用作回放。

## 数据与复现

- **FSS-1000** 为通用能力主指标。复用 EXP-008 的 2,400 个 query、随机参考及有放回协议；按 ID 配对。**COCO、LVIS** 为次要泛化检查。EXP-008 的 1/5-shot mIoU 依次是 FSS 85.20/86.55，COCO 66.33/70.14，LVIS 27.88/31.65，PASCAL-Part 31.92/34.72，PACO-Part 23.10/24.68。COCO 所有类别参与了基线训练。
- **PACO-Part** 可以开发或训练，也可以测试。锁定互斥的 train/dev/test 图像 ID，按父图去重；若声称新类别泛化，再按 object:part 类别留出并排除跨集合图像。PACO-LVIS 与 COCO/LVIS 共享部分图像来源，要对照 EXP-008 的训练图清单报告重叠。1/5-shot 按原 loader 分别覆盖 303/198 类；分析 shot 增益需公共类、公共 query。严格无部件监督版本只在对象域定参数，PACO 开发用标签选参要披露。[PACO 数据说明](https://github.com/facebookresearch/paco/blob/main/docs/PACO_DATASET.md)
- **PASCAL-Part** 和 **PartImageNet** 作冻结后外测。前者沿用 EXP-008 的对象框裁剪及四折等权。后者已接入独立的整图评估：显式传入官方保留集 part JSON 与图像根目录，直接使用 JSON 中的部件类别 ID，合并同图同类非 crowd 标注，每个有效 (类别, query) 一例；同类支持来自不同非查询图像且无放回，不足 K+1 张的类排除。按 seed、类、query 确定抽样，审计日志记录 ID。与框裁剪的 PACO/PASCAL 分栏，同一清单先测原版 Small。正式结果需记录发布版本、标注哈希、有效类及 query 数；不可直接与交互 NoC 比较。[PartImageNet 官方数据](https://github.com/TACJu/PartImageNet)

在 UFSAM2 源码目录以 EXP-008 的数据路径和第 5 轮 adapter 运行；示例为单折，四模式需用不同输出目录。正式比较沿用 EXP-008 的运行包装、数据清单及机器配置；若用外部脚本直接调用 eval_fss，可设置 model.granularity 和 model.audit_candidates。审计日志只在预测之后读取查询真值。

```bash
python inference_fss.py --sam2_version small --adaptformer_stages 2 3 --channel_factor 0.8 --resume "$ADAPTER" --data_root "$DATA_ROOT" --dataset_file pascal_part --fold 0 --shots 1 --prompt mask --seed 0 --num_workers 0 --granularity both --audit_candidates --name_exp exp009_pasc_f0_s1_both
```
